Compare with MATLAB

An independent check of the simulator behind this page. The battery model, the conventional ACC and the battery-aware MPC with constant-speed preview were re-written from scratch in MATLAB R2024b (24.2, Update 5; the MPC solves each step with the Optimization Toolbox's quadprog) and run on 10 fixed windows at regen efficiency 0.65 and 35 kW. Below, the page's own engine is run on the same 10 lead-speed traces and compared with MATLAB and with the paper's Python.

Scope and limits

  • What was checked: the frozen BMW i3 physics with realistic regen, the conventional ACC and the MPC with constant-speed preview, on 10 test windows. The website matches MATLAB to 0.000% (ACC) and 0.002% (MPC); the paper's Python (OSQP solver) differs from MATLAB by up to 0.159%, and from the website by up to 0.159%; the browser and MATLAB both use interior-point solvers (Clarabel, quadprog), while the Python run used OSQP, so small solver-tolerance differences are expected.
  • What was not checked: the map-aware MPC for speed breakers, V2V forecasts, SAC and safe SAC, SMC and the cut-in scenarios have no MATLAB port.
  • Same author, both ports. This checks that the implementation is consistent (solver, indexing, units). It does not check the physical model against a real car's measurements.
  • Windows: the 10 windows come from the connected-vehicle (V2V) test set, not the 160 windows in "Run it yourself", so the website was run on them through its upload path with the exact traces (checksums verified). The pass rule was written down before any website number was computed.

Code: code/matlab/verify_main.m in the repository (needs MATLAB R2024b and the Optimization Toolbox). Archived release: 10.5281/zenodo.24186267.
